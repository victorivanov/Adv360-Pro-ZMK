# Agent notes — Adv360-Pro-ZMK

ZMK firmware config for the Kinesis Advantage 360 Pro. See [README.md](README.md) for build setup (GitHub Actions or local container), flashing, and user-facing configuration options.

## Layout

- `config/adv360.keymap` — the single shared keymap (Devicetree source). Both `adv360_left.keymap` and `adv360_right.keymap` are thin wrappers that `#include` it; edit the shared file.
- `config/macros.dtsi` — user macros included by the keymap.
- `config/version.dtsi` — regenerated by `bin/get_version_local.sh` on every `make` and then restored via `git checkout`. Never commit changes to it; a failed build leaves it dirty — restore manually with `git checkout config/version.dtsi`.
- `config/boards/arm/adv360/` — board definitions; `adv360_{left,right}_defconfig` hold the Kconfig toggles the README describes.
- `config/west.yml` — pins the Kinesis ZMK fork (not base ZMK) that everything builds against.
- `config/keymap.json` / `config/info.json` — metadata for the GUI keymap editor; hand edits to `adv360.keymap` are not reflected there automatically.
- `bin/build.sh` — the actual `west build` invocations run inside the container by both `make` and CI (`.github/workflows/build.yml`).
- `bin/build_and_deploy.sh` — interactive build + flash flow for both halves, DON'T USE unless debugging the script itself, only for user application (uses `build_and_promote.sh`, `promote.sh`, and `deploy.sh`; `firmware/ACTIVE` records the promoted version).
- `firmware/` — build output (`.uf2` files land here).

## Conventions

- The main branch is `V3.0`, not `main`.
- Keymap/behavior files are Devicetree (`.keymap`/`.dtsi`) — C-style includes, node syntax, `&` behavior references.
- There are no tests; verification is that the firmware compiles (`make left` is the fastest check locally, or let CI build on push).
- `make` works in non-interactive shells (background tasks, CI): the Makefile only passes `--interactive --tty` to `docker run` when stdin is a real TTY.
